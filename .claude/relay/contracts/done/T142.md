## Baglam

VidShrink'in ayirt edici iddiasi **dinamiklik**: sabit 2 sn'lik pencereleri kore kore
ornekleyen araclardan farkli olarak, orneklemeyi icerige gore yerlestirmek. Bu duzenek
depoda **var** ve calisiyor:

`src/VidShrink.Ffmpeg/ComplexityProbe.cs`

- `PlanWindowCount(duration, heterogeneity, windowSeconds)` — pencere sayisini
  **heterojenlige** gore secer; duz bir klipte az, degisken bir klipte cok pencere.
- `PlanWindows(plan, duration, secondBits, sceneCuts, windowCount, windowSeconds)` —
  pencereleri **sahne kesiklerine** gore yerlestirir, `SampleWindow(Start, Length, Weight)`
  dondurur; pencere uzunlugu ve agirligi pencere basina degisebilir.
- `Heterogeneity(secondBits)` — saniye basi bit profilinden degiskenligi olcer.

`src/VidShrink.Ffmpeg/CalibrationProbe.cs` bu duzenegin **hicbirini** kullanmiyor.
Kendi ayri, sabit kopyasi var (`:9-11`, `:133-147`):

```csharp
private const double WindowSeconds = 2.0;
private const int MaxWindows = 3;
private const int MinWindows = 2;

private static IEnumerable<double> Windows(MediaInfo info, SpeedMode speed)
{
    var duration = info.DurationSeconds;
    if (duration <= WindowSeconds * 1.5) { yield return 0; yield break; }

    var usable = Math.Max(0.0, duration - WindowSeconds);
    var count = duration < WindowSeconds * 6 || speed == SpeedMode.Fast ? MinWindows : MaxWindows;
    for (var i = 0; i < count; i++)
        yield return usable * (i + 0.5) / count;
}
```

Uc kusur var, ucu de olculebilir:

1. **Sahne korlugu.** Pencereler `usable * (i + 0.5) / count` ile **esit araliklarla**
   yerlestiriliyor. Icerikte ne oldugu hic sorulmuyor. Uzun bir kaynakta uc pencere de
   ayni sahneye dusebilir, ya da ucu de siyah gecise dusebilir.
2. **Heterojenlik korlugu.** Pencere sayisi yalniz **sureye** ve `SpeedMode`a bakiyor.
   Bastan sona ayni olan bir klip ile her saniyesi degisen bir klip **ayni sayida**
   pencere aliyor. `PlanWindowCount` tam bunu cozuyor ama cagrilmiyor.
3. **Tavan uc.** `MaxWindows = 3` — sure ne olursa olsun. Uzun ve degisken bir kaynakta
   uc ornek kalibrasyon egrisini tasimaya yetmiyor olabilir. `ComplexityProbe`in tavani
   ayri bir sabit; ikisi sessizce farkli.

Kalibrasyon yoklamasi **CRF ile bit hizi arasindaki egriyi** olcer; bu egri hedef boyutu
tutturan tum plani belirler. Yanlis yerden alinmis iki ornek tum kodlamayi yanlis noktaya
oturtur.

Cagiran tek yer: `src/VidShrink.App/MainWindow.axaml.cs:1783`. **O dosyaya dokunma**,
`owns` disinda ve baska bir sozlesmenin.
